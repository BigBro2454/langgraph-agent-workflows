Hierarchical Blog
Writing System

A production-style multi-agent workflow built with LangGraph. A top-level supervisor orchestrates two specialized sub-teams — a Research Team and a Writing Team — to autonomously produce a complete, structured blog post from a single user prompt.

Architecture Overview

The system is composed of three interconnected StateGraph instances. The two sub-graphs (Research, Writing) are compiled and embedded as first-class nodes inside the top-level graph, giving each team complete autonomy over its own internal routing.

Top-Level Supervisor

The root orchestrator. It evaluates the global conversation state and decides whether to delegate work to the research_team, the writing_team, or to terminate by returning FINISH.

Routing decisions are made using a Pydantic model (SuperRoute) with structured LLM output, guaranteeing the response is always one of three valid transitions.

SuperRoute — structured routing schema python 
class SuperRoute(BaseModel):
    next: Literal["research_team", "writing_team", "FINISH"]

super_supervisor = super_prompt | llm.with_structured_output(SuperRoute)
ℹ️

The supervisor node is a LangChain Runnable chain (prompt | llm), not a plain Python function. LangGraph handles invocation transparently at runtime.

State Management

All three graphs share a single State schema. The add_messages reducer ensures messages from every agent — across all sub-graph levels — are appended rather than overwritten, building up rich shared context as the workflow progresses.

messages
Annotated[list[BaseMessage], add_messages]

Accumulates the full conversation history. Every node reads from and appends to this list. The reducer handles safe merging across parallel branches.

next
str

Written by each supervisor to signal the routing target. Conditional edges read this field to determine the next node to activate.

state definition python 
from typing import Annotated, TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
    next: str
▶️

Execution Flow

1

User prompt injected as a HumanMessage

The run begins with a single HumanMessage added to the initial state, e.g. "Write a blog post about multi-agent systems."

2

Top-Level Supervisor routes to research_team

The supervisor evaluates the state and determines research must come first. It sets next = "research_team".

3

Research sub-graph runs its internal loop

The Research Supervisor cycles between search and scraper agents. When satisfied, it returns FINISH and all messages flow back to the top-level state.

4

Top-Level Supervisor routes to writing_team

Seeing the research in context, the supervisor delegates to the writing team to draft the final post.

5

Writing sub-graph produces the final output

The Writing Supervisor orchestrates note-taking, chart generation, and final authoring. On completion, it returns FINISH.

6

Top-Level Supervisor returns FINISH → END

The top-level supervisor terminates the graph. The final blog post lives within state["messages"].

Lines 33–39 Worker Agent Nodes — search & scraper hierarchical_blog_writer.py 
def search_agent_node(state: State):
    response = llm.invoke([
        SystemMessage(content="You are a search agent. Find relevant information...")
    ] + state["messages"])
    return {"messages": [HumanMessage(content=response.content, name="search_agent")]}

def web_scraper_agent_node(state: State):
    response = llm.invoke([
        SystemMessage(content="You are a web scraper. Extract detailed data...")
    ] + state["messages"])
    return {"messages": [HumanMessage(content=response.content, name="web_scraper_agent")]}
Node signature — every node receives the full State dict and returns a partial state update. LangGraph merges it using the declared reducers.
SystemMessage prepended — the agent's persona is injected at call time, giving each worker a distinct role without separate model instances.
name= on HumanMessage — tagging the message with the agent's name lets other nodes and the supervisor distinguish who said what when reading state["messages"].

Lines 41–50 Research Sub-Graph — assembly & conditional edges hierarchical_blog_writer.py 
research_builder = StateGraph(State)
research_builder.add_node("supervisor", research_supervisor)
research_builder.add_node("search_agent", search_agent_node)
research_builder.add_node("web_scraper_agent", web_scraper_agent_node)

research_builder.add_edge("search_agent", "supervisor")
research_builder.add_edge("web_scraper_agent", "supervisor")
research_builder.add_conditional_edges(
    "supervisor",
    lambda x: x["next"],
    {"FINISH": END, "search_agent": "search_agent", ...}
)
research_builder.add_edge(START, "supervisor")
research_graph = research_builder.compile()
add_node — registers a callable (function or LCEL chain) under a string name. The supervisor is a chain; the agents are plain functions.
Worker → supervisor edges — agents always return to the supervisor after running. This creates the supervisor loop pattern.
add_conditional_edges — the lambda reads state["next"] (set by the supervisor) and dispatches to the matching node name, or to END which terminates this sub-graph and returns control to the parent.
compile() — validates the graph (no dangling edges, all nodes reachable) and returns a CompiledGraph that behaves like a regular callable — ready to be embedded as a node in the parent graph.

Lines 90–114 Top-Level Graph — embedding sub-graphs as nodes hierarchical_blog_writer.py 
class SuperRoute(BaseModel):
    next: Literal["research_team", "writing_team", "FINISH"]

super_supervisor = super_prompt | llm.with_structured_output(SuperRoute)

super_builder = StateGraph(State)
super_builder.add_node("supervisor", super_supervisor)
# Compiled sub-graphs are added just like any function node
super_builder.add_node("research_team", research_graph)
super_builder.add_node("writing_team", writing_graph)

super_builder.add_edge("research_team", "supervisor")
super_builder.add_edge("writing_team", "supervisor")
super_builder.add_conditional_edges(
    "supervisor", lambda x: x["next"],
    {"FINISH": END, "research_team": "research_team", "writing_team": "writing_team"}
)
super_builder.add_edge(START, "supervisor")
super_graph = super_builder.compile()
Sub-graphs as first-class nodes — research_graph and writing_graph are compiled CompiledGraph objects. Passing them to add_node makes LangGraph treat the entire sub-graph as a single opaque node — it runs its full internal loop and exits before the parent continues.
State propagation — because all graphs share the same State schema, messages produced inside a sub-graph are automatically merged back into the parent state when the sub-graph's END is reached.
Same routing pattern — the top-level supervisor uses the identical state["next"] conditional edge pattern as the sub-supervisors, keeping the mental model consistent at every level.
